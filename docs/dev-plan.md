# 개발 계획 (1단계: 게임 리스트업)

## MVP 범위
- 포함: 게임 목록(카드형), 검색·카테고리 필터, 상세 페이지(요약·원본 링크·준비물·말씀), 팁 댓글 + 좋아요, 후기(별점 + 짧은 글), 카카오 로그인, 관리자 페이지(등록·수정·심의 승인/거절·댓글 숨김), 링크 입력 시 메타데이터 자동 추출(반자동 수집), 신천지 금지 안내, 약관·개인정보처리방침
- MVP 이후: 자동 스크래핑(GitHub Actions), 필터링 설정 페이지, 스크래핑 현황
- 나중에: 찜/책갈피, 교회 정보, 판매·결제·광고, 사용자 판매, 교회 대항전

## 일정 (준비 기간 제외 약 5주)
- [x] 0주차: GitHub 저장소 생성
- [ ] 0주차: Cloudflare·Neon·Firebase·카카오 디벨로퍼스 가입, 노션 게임 DB에 게임 30~50개 수집, 서비스 이름 임시로 정하기
- [x] 1주차: 프로젝트 뼈대 (목록·검색·필터·상세, 샘플 데이터)
- [ ] 1주차: Cloudflare Pages 자동 배포 연결
- [ ] 1주차: Neon 스키마 작성(심의 칼럼 포함)·연결, 노션 게임 데이터 옮겨오기
- [ ] 2주차: 목록·상세를 실제 데이터로(승인된 게임만 노출), 검색 개선
- [ ] 3주차: 관리자 페이지(게임 등록·수정, 심의 대기 목록 승인/거절), 링크 입력 시 제목·설명·썸네일 자동 추출(Cloudflare Workers)
- [ ] 4주차: 카카오 로그인, 팁 댓글 + 좋아요, 후기
- [ ] 5주차: 모바일 점검, 약관·개인정보처리방침, 지인 10~20명에게 먼저 공개

## MVP 이후 (자동 수집)
- [ ] GitHub Actions 정기 스크래핑 (RSS 우선, 결과는 `status: 'pending'`으로 저장)
- [ ] 자동 필터링 규칙 (제외 키워드, 영상 길이, 콘텐츠 나이)
- [ ] 필터링 설정 페이지 (자동 승인 vs 수동 승인, 소스별 설정)
- [ ] 스크래핑 현황 페이지 (선택)

## 확장 대비 설계
- 게임 테이블의 `kind` 필드(외부 링크 / 자체 판매 / 사용자 판매)로 2·3단계 게임을 같은 목록에 섞을 수 있게 함
- 게임 테이블의 `status`·`auto_scraped` 필드로 수동 입력과 자동 수집 게임을 같은 심의 흐름에 태움
- 회원 테이블에 교회·전화번호 칸을 미리 두되 4단계 전까지 받지 않음
- 결제: 토스페이먼츠 또는 포트원 / 광고: 구글 애드센스, 카카오 애드핏 / 대항전: 실시간 기능은 그때 검토 (Cloudflare Durable Objects 등)
