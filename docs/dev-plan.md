## MVP 범위
- 포함: 게임 목록(카드형), 검색·카테고리 필터, 상세 페이지(요약·원본 링크·준비물·말씀), 팁 댓글 + 좋아요, 후기(별점 + 짧은 글), 카카오 로그인, 관리자 페이지(등록·수정·심의 승인/거절·댓글 숨김), 링크 입력 시 메타데이터 자동 추출(반자동 수집), 신천지 금지 안내, 약관·개인정보처리방침

- 나중에: 찜/책갈피, 교회 정보, 판매·결제·광고, 사용자 판매, 교회 대항전

## 관리자 화면 개선 (2026-11-28 추가, 순서대로 PR 하나씩)
- [x] ① 거절된 게임 영구 삭제 (#29)
  - 거절 상태의 세부 화면에서만 [영구 삭제]를 누를 수 있고, 확인 팝업을 거친다. 서버는 `delete ... where id = ? and status = 'rejected'`처럼 조건을 붙여 지운다. 그 사이에 다시 승인된 게임은 지우지 않는다
  - `collect_seen`은 남긴다. 그래서 자동 수집이 같은 글을 다시 가져오지 않는다
  - 지우면 거절 사유와 심의 기록도 함께 사라진다(기록 표 없음). owner·admin 모두 지울 수 있고 확인 팝업을 거친다 (decisions 2026-11-28)
- [ ] ② 심의 목록 페이징
  - 탭마다 20개씩 보여 주고 주소는 `?status=approved&page=2`처럼 쓴다. 관리자 화면이고 쪽 번호가 필요해서 offset 방식으로 한다
  - 순서가 매번 같도록 정렬 끝에 `id`를 붙인다. 개수는 지금 쓰는 `countGamesByStatus`로 센다. 범위를 넘은 쪽 번호는 마지막 쪽으로 보낸다
  - 모바일에서는 [이전]·[다음] 버튼과 `3 / 12쪽` 표시
- [ ] ③ 자동 수집 시각·주기를 화면에서 바꾸기 (SQL 실행 + `collect:deploy` 필요)
  - Cloudflare cron은 배포할 때 정해져서, 실행 중에 바꾸려면 사이트에 Cloudflare API 토큰을 넣어야 한다. 그래서 cron은 매시 정각(`0 * * * *`)에 깨우기만 하고, 언제 돌지는 DB 설정으로 정한다
  - `collect_settings`에 `run_hour`(KST 0~23시)와 `every_days`(1·2·3·7일) 칼럼을 추가한다. collector용 함수 `collect_due()`는 'run'·'off'·'wait' 중 하나를 돌려준다. 정해진 시각이고 마지막 성공에서 정한 날수가 지났을 때만 'run'이다
  - 'wait'는 DB에 기록하지 않는다. 기록하면 하루 24줄이 쌓여서 60줄 기록이 2~3일 만에 밀린다. 'off'는 정해진 시각에만 기록한다
  - 비용은 하루 24번 깨어나고 한 번에 DB 쿼리 1개다(무료 한도 안). 하루 여러 번 돌리기는 AI 비용과 심의량 때문에 넣지 않는다
  - 순서: SQL 실행 → `collect:db-check`(함수 5개) → `collect:deploy`. 거꾸로 하면 함수가 없어 매시 'failed'가 쌓인다
  - 화면에는 '다음 실행 예정'을 보여 준다

## 확장 대비 설계
- 게임 테이블의 `kind` 필드(외부 링크 / 자체 판매 / 사용자 판매)로 2·3단계 게임을 같은 목록에 섞을 수 있게 함
- 게임 테이블의 `status`·`auto_scraped` 필드로 수동 입력과 자동 수집 게임을 같은 심의 흐름에 태움
- 회원 테이블에 교회·전화번호 칸을 미리 두되 4단계 전까지 받지 않음
- 결제: 토스페이먼츠 또는 포트원 / 광고: 구글 애드센스, 카카오 애드핏 / 대항전: 실시간 기능은 그때 검토 (Cloudflare Durable Objects 등)
