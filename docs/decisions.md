# 결정 기록

새 결정을 내리면 위에 추가합니다. (날짜 · 결정 · 이유)

## 2026-11-19
- **배포는 Cloudflare Pages가 아니라 Workers + OpenNext 어댑터(`@opennextjs/cloudflare`).** Cloudflare가 풀스택 Next.js를 Workers로 안내하고, Pages용 `next-on-pages`는 Edge 런타임만 지원해 더는 권장되지 않는다. Cloudflare 기본 추천인 vinext는 베타라 정식 버전인 OpenNext를 골랐다. (2026-11-11 기술 스택 결정의 'Cloudflare Pages' 부분을 대체)
- **렌더링은 SSR부터, 캐시(ISR)는 나중에.** ISR은 R2·Durable Objects 큐 등 설정이 늘어나는데 게임 수십 개 규모엔 과하다. SSR이면 `DATABASE_URL`이 런타임에만 필요해서 CI 빌드에 비밀키를 넣지 않아도 된다. 느려지면 그때 캐시를 붙인다.
- **관리자 로그인은 Better Auth(이메일+비밀번호), 역할은 최고 관리자(`owner`) / 관리자(`admin`) 2단계.** 최고 관리자만 관리자 계정을 추가·초기화·역할 변경·삭제하고, 관리자는 게임 등록·수정·심의를 한다. 사람마다 권한을 다르게 주고 누가 승인했는지 남기기 위해서다. 공개 가입은 막는다.
  - 새 관리자는 최고 관리자가 이메일로 추가하면 임시 비밀번호가 화면에 한 번 표시되고, 최고 관리자가 직접 전달한다. 첫 로그인 때 비밀번호 변경을 강제한다. 메일 자동 발송은 도메인이 필요해 하지 않는다.
  - Cloudflare Access는 뺐다. workers.dev 주소에서는 `/admin` 경로만 보호할 수 없고 Worker 전체가 막힌다. 공용 비밀번호 하나로 막는 방식은 사람별 권한을 줄 수 없어 뺐다.
  - 직접 구현 대신 Better Auth를 고른 이유: 비밀번호 해시·세션 같은 보안 코드를 직접 검증하기 어렵다. 라이브러리를 쓰면 확인할 대상이 설정과 흐름으로 줄어든다.
  - 시험(spike) 결과: Neon HTTP 드라이버(`kysely-neon`)로 동작하고, 공개 가입 차단·역할별 권한·시도 횟수 제한 11개 시나리오를 통과했다. 해시는 Workers CPU를 아끼려고 기본 scrypt 대신 Web Crypto PBKDF2(10만 회)를 쓴다. 측정해 보니 CPU는 로그인보다 콜드 스타트 비용이 컸다(기존 목록 페이지도 요청당 160ms 이상, 에러 0).
  - 일반 사용자 로그인은 2026-10-31 결정대로 카카오 로그인이며, 구현 방식은 4주차에 따로 정한다.
- **소스 종류(`source_type`)는 블로그·유튜브·인스타그램·기타 4개로 고정.** 문서에만 있던 '노션' 소스는 따로 두지 않고 '기타'로 넣는다. 노션 공개 페이지로 공유되는 게임이 드물어 DB 제약조건까지 바꿀 이유가 없다.

## 2026-11-15
- **노션 게임 데이터를 Neon으로 옮기는 작업은 뺀다.** 노션 게임 DB에 아직 옮길 데이터가 없다.
- **심의 status는 영어 3개: `pending` / `approved` / `rejected`.** DB 값은 코드·Workers에서 다루기 쉬운 영어로 두고 화면에서 한국어로 보여준다. `modified`는 상태가 아니라 행동이라 뺐고, 수정 여부는 `updated_at`으로 안다. (기존 Supabase 초안의 한국어 status를 대체)
- **Neon 스키마는 `games` 테이블만 먼저.** 회원·댓글·후기는 로그인 방식이 정해지는 4주차에 만든다. 인증이 미정인 채로 회원 테이블을 만들면 다시 고칠 가능성이 크다.
- **권한은 DB(RLS)가 아니라 서버 코드가 판단.** Neon에는 Supabase의 auth·RLS가 없다. 브라우저는 DB에 직접 붙지 않는다.
- **Neon 연결 환경변수는 `DATABASE_URL` 하나로 통일.** Neon 대시보드 기본 이름이고, 실행 위치(Next.js·Workers·Actions)마다 이름을 다르게 둘 이유가 없다.
- **깃 플로우는 GitHub Flow 간소화, 병합은 Squash만.** Git Flow는 1인 개발 + main 자동 배포에 과하다. Squash는 main의 커밋 1개가 기능 1개가 되어 읽고 되돌리기 쉽다. (자세한 규칙: `docs/git-flow.md`)
- **규칙은 시스템으로 강제: PR 빌드 CI + main 브랜치 보호(관리자 예외).** 글로만 둔 규칙은 사람도 AI도 놓친다. public 저장소라 둘 다 무료다.
- **브랜치 설명은 영어 kebab-case.** 처음엔 한글을 골랐지만 Cloudflare Pages가 영문·숫자 외 글자를 `-`로 바꿔 미리보기 별칭이 겹칠 수 있어 바꿨다.

## 2026-11-11
- **자동 스크래핑(GitHub Actions)은 MVP 이후로.** 5주 일정에 넣으면 로그인·댓글·후기가 밀린다. 첫 공개는 진선이 큐레이션한 30~50개와 반자동 수집(링크 입력 시 메타데이터 자동 추출)으로 충분하다.

## 2026-11-10
- **기술 스택: Next.js + Tailwind + Cloudflare Pages/Workers + Neon PostgreSQL + Firebase Storage + GitHub Actions.** 완전 무료로 시작할 수 있고 광고를 포함한 상업 사용이 가능하다. 비용은 트래픽이 늘 때만 생긴다. (2026-10-31의 Supabase + Vercel 결정을 대체)
- **콘텐츠 수집은 반자동(A)과 자동 스크래핑(B)을 함께 지원.** 반자동은 품질 관리가 쉽고, 자동은 콘텐츠를 풍부하게 만든다.
- **초기 심의 방식은 수동 승인.** 자동 수집 콘텐츠는 `pending`으로 저장하고 진선이 승인해야 노출한다. 소스별로 자동 승인을 켤 수 있지만 품질 관리가 먼저다.

## 2026-10-31
- **코드 작업은 로컬 터미널의 Claude Code에서, 변경은 PR로 리뷰 후 병합.** AI가 바로 main에 올리면 빠르지만 판단·리뷰할 기회가 없어 AI-Native Engineer 역량을 키우기 어렵다.
- **기술 스택: Next.js + Tailwind + Supabase + Vercel.** 무료로 시작 가능, AI가 잘 다룸, 결제·광고·실시간 기능을 나중에 붙이기 쉬움. (→ 2026-11-10에 변경)
- **1단계 MVP는 외부 게임 리스트업만.** 판매·대항전은 사용자와 콘텐츠가 모인 뒤에.
- **댓글·후기는 로그인 사용자만(카카오 로그인).** 신천지 등 악성 사용자 차단에 유리.
- **외부 게임은 요약 + 원본 링크로만 소개.** 원본 복사는 저작권 문제.
- **협업 문서는 노션.** 진선은 워크스페이스 멤버가 아닌 페이지 게스트로 초대 (멤버가 2명 이상이면 무료 블록 한도가 생김).
